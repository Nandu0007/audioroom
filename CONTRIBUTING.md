# Contributing to AudioRoom Ninja

We love your input! We want to make contributing to AudioRoom Ninja as easy and transparent as possible, whether it's:

- Reporting a bug
- Discussing the current state of the code
- Submitting a fix
- Proposing new features
- Becoming a maintainer

## Development Process

We use GitHub to host code, to track issues and feature requests, as well as accept pull requests.

### Pull Requests

1. Fork the repo and create your branch from `main`.
2. If you've added code that should be tested, add tests.
3. If you've changed APIs, update the documentation.
4. Ensure the test suite passes.
5. Make sure your code lints.
6. Issue that pull request!

### Code Style

* Follow [Dart Style Guide](https://dart.dev/guides/language/effective-dart/style)
* Use meaningful variable and function names
* Add comments for complex logic
* Write unit tests for new features
* Run `flutter format .` before committing

### Commit Messages

Use clear and meaningful commit messages:
- `feat: add voice effects service`
- `fix: resolve audio playback issue`
- `docs: update API documentation`
- `test: add gamification service tests`

## Bug Reports

**Great Bug Reports** tend to have:

- A quick summary and/or background
- Steps to reproduce
- Be specific!
- Give sample code if you can
- What you expected would happen
- What actually happens
- Notes (possibly including why you think this might be happening, or stuff you tried that didn't work)

## Feature Requests

We welcome feature requests! Please:

1. Check existing issues first
2. Provide detailed use cases
3. Explain why this feature would be useful
4. Consider the scope and complexity
